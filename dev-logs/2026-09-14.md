# 2026-09-14 开发日志

## 本次完成：v1.10.20 日期识别严格化 + 历史日期重整 + 展示统一 YYYY/MM/DD

### 背景

用户反馈「关于导入的日期还是有问题」，要求：① 先识别年月日（几几年几月几日）再记录；② 记录/展示的日期格式做成 `YYYY/MM/DD`；③ 本次更新把现有历史记录一次性重整为该格式。

确认采用**方案 A**：存储层保持 ISO `YYYY-MM-DD`（60+ 处 SQL 依赖 `date >= ? AND date <= ?`、`strftime('%Y-%m', date)` 按月归档，且 14 个 `<input type="date">` 只接受 ISO），展示与导出层统一改为 `YYYY/MM/DD`；历史数据用迁移 v25 重整。

### 完成事项

1. **日期识别严格化**
   - `data-normalizer.ts`：`normalizeDate(raw, { strict: true })` 严格模式（识别不出返回空串，不兜底「今天」、不原样返回）+ 导出 `parseDateStrict()`
   - `statement-parser.ts` / `bank-statement-parser.ts` / `wallet-bill-parser.ts`：所有日期解析改走 `parseDateStrict`，无法识别的行跳过并计数，解析结果附「有 N 行日期无法识别已跳过」提示；`parseStandardLine` 不再生成空日期交易（此前会把表头/脏行变成一条空日期交易）
   - 写库路径：`account-transaction-service.importWalletBills`、`bank:importParsed`、`trade:importParsed` 先识别日期，识别不出的行跳过并计入 `errors`
2. **迁移 v25（历史日期重整）**：动态扫描所有「以 `date` 结尾的 TEXT 列」，把非 ISO 写法统一重整为 ISO；无法识别的值保留原值；唯一约束冲突（如 `exchange_rates.date`）逐行跳过不阻断迁移；不触碰 `updated_at`/`created_at`
3. **展示与导出统一 `YYYY/MM/DD`**：新增 `src/shared/utils/date-format.ts`；日常收支、存取记录、投资交易、券商现金流水、定期存款起止日、保单生效日、账户最近交易、投资收益明细、报表导出 Excel 全部接入
4. **导入提示不再被吞掉**：银行/券商导入弹窗与钱包流水页在「识别成功但有日期问题」时也显示原因

5. **板块内滚动全覆盖（用户追加要求）**
   - Table 组件：`scrollable` 未传 `maxHeight` 时默认 420px（约 10 行可视），调用处只写 `scrollable` 即可
   - 新增全局容器类 `.panel-scroll` / `.panel-scroll--table`（global.css），供卡片式长列表使用
   - 补齐板块：微信/支付宝收支流水（WalletFlow）、记账流水（Bookkeeping）、股票交易历史弹窗（TradeHistoryModal）、股票查询与分析结果（Dashboard）、今日交易（Investments）、当日成交明细（DailyTradesReport）、按标的已实现盈亏（RealizedPnlCard）、每日卖出明细（RecentSellPnlCard）、币种列表（Settings）、自定义银行/券商格式列表（BankFormatCard/BrokerFormatCard）
   - 卡片式长列表：保单（Insurance）、定期存款（FixedDepositsSection）、人情债（SocialObligations）、AI 报告归档（AIAssistant）
   - 未改动：首页「资产概览」账户汇总（「💎 总资产」行需始终可见）、AI 会话侧栏与聊天区（本就有 60vh / 独立滚动）、导入预览（已有 300~360px 滚动）
